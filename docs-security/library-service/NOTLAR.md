Auth kaynaklarını (HttpAccountDataEraser, ServiceTokenIssuer) geçici dizine derler; JDK 25 ve repository checkout gerekir.

## Auth entegrasyonu (kullanıcı JWT ve D4)

- **Kullanıcı JWT:** Library, Auth'un gerçek access token'ını JWKS ile yerel doğrular (`typ=at+jwt`, RS256, `iss`, `aud=ltz-api`, `kid`, `iat/nbf/exp`, `sub` kanonik UUID, `roles` allowlist'i). Canlı Auth ile 30 Ekim 2026'da doğrulandı; ayrıntı: `docs-library/LTZ-HAM-LIB-06-Auth-Entegrasyonu-Sonuc.md`.
- **İptal gecikmesi (Auth politikası, Library'ye özgü açık değil):** Auth introspection/iptal listesi sunmaz; Library oturum veya hesap iptalini token süresi dolana kadar (+ en çok 30 sn saat toleransı) görmez. `docs/api.md` Auth politikası prod için 60 sn der; dev ortamında gözlenen access token ömrü 900 sn'dir. Kritik bir işlem için daha kısa pencere gerekirse Auth ile ayrı bir sözleşme gerekir (Library tek başına çözemez).
- **İç okuma uçları:** Recommendation sinyal ucu artık Auth'un `signals:read` sözleşmesindedir (`sub=svc:recommendation-service`, imzalı `account_id` == yoldaki hesap; eski `library:recommendation:read`/`target_user_id` kalktı). Profil iç uçları (`library:profile:read`, `viewer_id`) eski taslaktır: Auth karar K1 gereği delegasyon token'ı üretmez, User kullanıcının kendi at+jwt'siyle public uçları çağırır; bu iç uçlar kapalı kalır ve `DEPRECATED`'dır. Ayrıntı: `docs-library/LTZ-HAM-LIB-07-Auth-Karar-Uyarlamasi-Sonuc.md`.
- **Library → User gizlilik kararı (LIB-11/LIB-14):** `UserServiceLibraryVisibility` User'ın `POST /internal/v1/privacy/decisions` ucunu çağırır: PROFILE → `field=LIBRARY`, RECOMMENDATION → `field=RECOMMENDATION` (`viewerId = ownerId`). Yalnız `allowed` okunur (`setting`/`friends` yok sayılır); eksik/yinelenen/yabancı sahip, HTTP hatası, yönlendirme, zaman aşımı, token yokluğu ve boş adres `UNAVAILABLE` (503) olur; retry ve cache yoktur. Token: `privacyDecisionToken()` (`privacy:read`, `sub=svc:library-service`, 60 sn); `events:ingest` bunun yerine geçmez. Sır `AUTH_LIBRARY_SERVICE_CLIENT_SECRET` tanımsızsa istemci kapalıdır. Compose artık sırrı library-service konteynerine de geçirir (2026-11-09; değer `.env.dev`'den gelir ve Auth ile aynıdır, kontrol hash ile yapıldı, değer yazdırılmadı). User `ltz.user.social.projection-enabled=false` iken başkasının koleksiyonuna `allowed=false` döndürür (403); bu bilinçli bir fail-closed davranıştır (Kerem, `library-cevap-01`). RECOMMENDATION bayraktan bağımsızdır ve açık rıza ister. Sözleşme User'ın `feature/user-service` dalındadır (commit `357213cc`, main'e alınması bekleniyor); gerçek User ile uçtan uca **NOT VERIFIED**.
- **Atlanan test yasağı:** merkezi coverage kapısı atlanan testi reddeder. Auth PR #36/#37 kaynağına bağlı gerçek-Auth testleri bu yüzden test ağacında yoktur; Auth dalda olunca eklenebilir.
- **Hesap silme (D4):** Auth 14 günlük bekleme sonrası çağırır; canlı Auth silme akışı doğrulanmadı (NOT VERIFIED). Sözleşme, Auth'un gerçek HTTP adaptörüyle `AuthErasureAdapterIntegrationTest` içinde sınanır.
- **Profil özeti olayı (LIB-10):** Koleksiyon değişince `library_summary_outbox` (V43) kullanıcıyı veriyle aynı transaction'da işaretler; relay mutlak sayıları gönderim anında okuyup `LibrarySummaryChanged` olarak User'ın `POST /internal/events` ucuna iletir (`events:ingest`). Kullanıcı başına tek işaret vardır; gönderim sırasında değişiklik olursa işaret kalır. Hata geri çekilmeyle (5 sn × 2^n, en çok 300 sn) sınırsız denenir. V43 var olan sahipleri bir kez işaretler. Hesap silinince bekleyen işaret silinir; ancak relay silmeden hemen önce almışsa tek bir sıfır sayılı olay gidebilir (User'da `profile_counters` FK'siz, satır yalnız userId ve sayı içerir, hiçbir uçtan okunamaz; Kerem kabul etti).
- **DEV dağıtımı (2026-11-09):** `library_db` yedeği alındı (scratchpad, Git dışı), `ltz/library-service:dev-rollback-v43` etiketi atıldı, yalnız library-service derlenip yeniden oluşturuldu; V43 uygulandı (DEV'de 0 koleksiyon kaydı vardı, başlangıç aktarımı boş). Sentetik bir kullanıcı işaretiyle relay → Auth token → DEV User `POST /internal/events` teslimi 2xx doğrulandı; User'da o kimlik için sıfır sayılı, hiçbir uçtan okunamayan bir `profile_counters` satırı kaldı (FK'siz). DEV User henüz `RECOMMENDATION` alanını bilmez (Kerem'in dalı main'de değil): RECOMMENDATION isteği 400 alır, Library bunu 503'e çevirir.
- **`contextLoads` ve geliştirici DB'si:** `LibraryServiceApplicationTests` `-Pci` dışında geliştirici DB'sine (`localhost:5542`, `ltz_dev`) bağlanır ve Flyway'i çalıştırır; bu yüzden V43 gibi yeni migration'lar o testle DEV `library_db`'ye uygulanır. Parolasız yerel koşuda `password authentication failed` ile düşer. DEV'e V43 yedek ve onayla uygulanmalıdır (Game DEV dağıtım prosedürü); testi bilinçsizce koşturma.
